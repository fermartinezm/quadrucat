'Gazebo': the policy node (ROS 2, 50 Hz) sends joint targets and Gazebo runs the PD (Kp 35, Kd 0.5, torque limits as in training) at every physics step, like the Go1's motor drivers (launch `pd:=gazebo`). The 'PD over ROS' columns instead compute the PD torques in the Python node at 500 Hz and send them through ros2_control. With the physics as fast as the PC allows (0.6-0.8x real time on the WSL laptop) the nodes compete with Gazebo for CPU and those torques arrive late; the '1/4 speed' columns cap the physics (`sim_rate_hz:=250`) so the same nodes keep up, which separates the physics gap from the communication delay. Each Gazebo seed is 3 repetitions at full speed (1 at 1/4 speed); the robot is not reset between commands, so after a fall the remaining commands count as falls. Feet count as on the ground when the foot centre is < 2.8 cm high (forward kinematics), MuJoCo uses its contact sensors, so the gait rows compare close but not identical definitions.
